En el Select, la primera cláusula que siempre tenéis que tener, básicamente indicamos el sistema que columnas nos interesan para nuestro análisis. Nuestra base de datos puede tener 50 columnas que a veces unicamente no se interesa alguna. Cuando yo quería hacer la suma de impresiones, realmente es una columna que me interesa. Tres opciones. Si queremos seleccionar todo, no debería pasar mucho, pero a veces si queremos seleccionar toda la base de datos, usamos un comodin, la estrella. Select estrella significa seleccionar todas las columnas. Si queremos una sola, la tenemos que designar por su nombre, select contra. No es como en Excel que podéis o no podéis tener un encabezado para una tabla. Aquí una columna siempre tiene un nombre asingado. Así que tenéis que encontrar el nombre de esta columna y de ahí lo ponéis aquí para seleccionar esta columna. Si queréis más de una, tenéis que indicar los diferentes nombres separados por una coma. Dos, veinte, cincuenta lo que queráis y en caso que queráis seleccionar todas, acotados del comodin y no está escribiendo ahí cada una de ellas. Muy importante, si trabajáis en Cloud, vale también el comentario si trabajáis en local, pero en Cloud más. Lo que va a ser cómo funciona SQL cuando estáis ejecutando algo en función de las columnas que pedís o donde aplicáis lógica, el sistema nada más va a escanear estas, no vuestra tabla completa, pero únicamente de las columnas que sirven. Entonces si tenéis una base de dato y no únicamente páis aplicar una lógica en dos columnas, pues al final la cantidad de datos que se está analizando es bastante inferior. Entonces si usáis el select estrella, vale, va a analizar toda la tabla de datos y en caso de un service of cloud os cobran por uso, vale, por lo tanto os va a cobrar más si hacéis una query con el select estrella que si usáis el select más el nombre de una columna. Aquí tenéis el ejemplo, veis arriba a la derecha os indica la cantidad de datos que se va a escanear. En la primera he usado el select estrella 42 gigabyte, en la segunda uso únicamente una columna tengo 1.4 gigabyte y como nos cobran por uso pues la empresa o vos otros y si soy el héroe la titular de cuenta vais a pagar más por la primera que por la segunda, por lo tanto es muy importante poner únicamente lo que necesitamos. El análisis de datos que están en cloud no es carro pero si siempre ponéis select estrella ahí sí que os puede ir un poco de las manos. Vale, cuando seleccionáis una o unas columnas le podéis cambiar el nombre, vale, es decir en vuestra base de datos tenéis una columna que se llama en este caso country, vale, que es el país de las visitas, pero le queréis cambiar el nombre, vale, en este caso yo le puse country user, varios motivos nos gusta el nombre o a veces los nombres son muy pocos descriptivos y mejor cambiarle el nombre. Para hacer esto es muy fácil, hacéis exactamente lo que hemos visto hasta ahora el select, más el nombre de la columna pero después le ponéis un as, vale, as y el nuevo nombre, eso significa en la query que veis aquí select country as country user significa seleccioname la columna country pero cambiarle el nombre para que sea country user y después seguís con el from y tal. Muy importante aquí el ejemplo podéis decir pues no tiene mucho sentido porque entre country y country user tampoco es que no cambia mucho, que es verdad pero cuando aplicáis lógicas matemáticas a una columna que lo vamos a ver más adelante lo que pasa es que el SQL os suele devolver un nombre un poco raro, vale, en vez de tener no sé clicks, vale, vais a tener f135, vale, ahí sí que le tenemos que cambiar el nombre porque si no no entendemos nada a los datos.
